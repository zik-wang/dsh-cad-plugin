DSH 独立制图验收

这个目录用于纠正上一版“现成图纸配方重放”与“DSH 自己制图”混淆的问题。
上版 cad-production 的三张配方、尺寸答案、建模脚本、CAD/PDF 成品均不提供给本次 DSH 会话。

职责：
DSH / DeepSeek 自己读取原图、建立尺寸记录、编写 Python/ezdxf 建模程序、修正代码、输出图纸。
外层只提供通用文件读写、原图/预览查看、Python 执行、DXF导出PDF与LibreCAD回读工具，不含具体零件参数或生成配方。
制图和独立审图均由原生DSH直接读取原图；无公司内网视觉服务依赖。

每个 jobs/任务目录下的 agent/ 存放 DSH 编写的源代码；artifacts/ 存放其生成结果；.host/history/ 保留每次写入版本和来源会话。
工具读写限于当前任务目录。Python文件访问记录和拒绝记录保留在 .host/python-access.jsonl；运行环境不含API Key。
这用于核对本次来源隔离与执行过程，不宣称构成可抵御恶意Python代码的安全沙箱。

独立制图与最终质量是两个不同验收项。即使代码确实由DSH编写，也必须检查尺寸、比例、几何完整性和排版，不能把执行成功当作图纸合格。

本机启动方式：
把新图片拖到“开始独立制图.cmd”上，创建一个全新任务，由安装的DSH原生headless引擎执行。也可运行 node run-image.mjs "图片绝对路径"。
已存在任务可用 node launch.mjs 任务ID --desktop 打开独立DSH桌面；任务运行期间请使用已有窗口，同一任务禁止同时启动桌面与后台引擎。
这里是当前电脑的接入包，依赖settings.json所列的已安装DSH/Python/LibreCAD和work/pydeps；不是脱离本机依赖即可运行的便携安装包。密钥从当前Windows用户的DPAPI加密文件读取，不写入图纸、代码或任务输出。

2026-11-10运行问题记录：
首次独立任务以后台DSH启动，随后打开共享会话目录的桌面DSH。桌面将进行中的轮次显示为异常中止，而后台仍有新的工具调用。
已停止该后台实例，保留历史与文件，并从桌面原生会话继续。之后增加任务运行实例检查，不同任务的状态目录分开，同一任务只允许一个DSH实例；重复启动测试返回拒绝码2。后台任务结束后可用桌面打开该任务的原生会话记录。
这是外层接入问题，不算作DSH制图完成或失败的尺寸验收结果。

桌面首轮代码使用了DSH桌面预设自带的write工具。该工具调用、内容、成功回执及代码哈希已从原生会话日志另行提取至.host/native-tool-events.jsonl、native-history及native-evidence.json；不是由外层补写建模代码。新桌面启动配置另覆盖其单独的agent预设，使后续任务只使用当前任务的CAD通用工具。

新图片批处理结束后会自动进行独立DeepSeek视觉/几何读回复核，最多由原DSH会话再修订两轮。quality-status.json记录每轮与实际图纸SHA256的对应关系。有问题或复核异常会保留输出并标needs_manual_review/review_failed，不冒充通过。复核模型本身也可能误读，DSH必须依据原图判断意见是否成立。

后续修复与当前边界：
累计90次请求限制曾错误截断已在修订的DSH，现已移除；仍保留单次32000 token上限。
桌面standard preset曾因不完整替换发生未知预设与compaction隔离错误，已按安装包原始分组恢复，仅调整相关工具权限。
首版因max-tokens未完成时支持原生同会话有限续跑；完整首版产生后继续独立复核，不能把文件存在当成通过。
review-job v5同时读取工程图与1:1模型，记录两份DXF及预览哈希；检查毫米单位、DXF结构和审核期间文件变化。
高推理复核产生空/无效JSON时记录尝试信息并降为low重试一次；最终失败仍记录review_failed。
定义点测量能发现部分文字覆盖差异，但未覆盖所有LINE+TEXT手画尺寸、相切关系、投影关联及槽特征语义。
当前三个任务已有文件，尚不能宣称全部工程精度合格。详细流程、实际提示词及失败复测记录见同级../dsh-workflow/workflow-detail.html和DSH_CAD_workflow.pdf。
